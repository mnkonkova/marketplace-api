# Телеграм-боты «PrMarket»

Два бота: **креаторский** (исполнителю) и **клиентский** (заказчику).
Третьего, менеджерского, нет и не будет — всё, что адресовано
менеджеру, уходит в общий чат менеджеров через CRM-вебхук API
(`N8N_WEBHOOK_URL`). Решение владельца от 25 сентября: второй канал
означал бы две очереди доставки, два места привязки и вопрос «куда
смотреть» на каждом дежурстве.

Сервис отдельный, потому что ходить в `api.telegram.org` и принимать
вебхук Telegram должен кто-то, до кого Telegram достучится, — а до
нашего VDS он ходить не обязан.

## Что он делает и чего не делает

Делает:

- принимает апдейты Telegram: `/start <код>` (привязка), блокировку
  бота, обычные сообщения;
- принимает уведомления от нашего API и рассылает их **адресатам,
  которых API уже посчитал**.

Не делает **намеренно**:

- не хранит состояние. Привязки, дневной потолок в 30 сообщений и
  «кого касается это событие» живут в API. Своя копия любого из этих
  правил — это два ответа на один вопрос и однажды два сообщения
  одному человеку;
- не ведёт переписку. Работа живёт в кабинете, и делать вид, что
  здесь можно что-то решить, нечестно;
- не пишет в лог ни токенов, ни секретов, ни сырого `init_data`.

## Переменные окружения

| Имя | Зачем |
|---|---|
| `TELEGRAM_CREATOR_BOT_TOKEN` | токен креаторского бота. Можно оставить пустым — тогда он просто не отвечает, а сервис поднимается |
| `TELEGRAM_CLIENT_BOT_TOKEN` | токен клиентского бота |
| `TELEGRAM_WEBHOOK_SECRET` | секрет в пути вебхука. Telegram шлёт апдейты без авторизации, и это единственное, что отличает его от любого, кто знает адрес |
| `API_BASE_URL` | адрес нашего API, например `https://wayprmarket.ru` |
| `BOT_SHARED_SECRET` | общий секрет группы `/api/v1/bot/*`. Тот же, что в `.env.prod` API |
| `BOT_WEBHOOK_SECRET` | ключ, которым API подписывает тело уведомления (`X-Signature`). Пусто — подпись не проверяется, и сервис об этом предупреждает при старте |
| `BOT_WEBHOOK_TOKEN` | bearer тех же уведомлений, если задан на стороне API |
| `APP_BASE_URL` | адрес кабинета: ссылки в сообщениях ведут туда, где человек сделает то, о чём его просят |
| `TELEGRAM_MANAGERS_CHAT_ID` | общий чат менеджеров. Туда уходит всё, что адресовано дежурному, и пишет туда креаторский бот — отдельного менеджерского нет. Пусто → такие сообщения не отправляются, и сервис говорит об этом при старте |
| `TELEGRAM_MANAGERS_THREAD_ID` | тема супергруппы, если чат разбит на темы. Пусто — общий поток |
| `TELEGRAM_MANAGERS_BOT` | каким ботом писать в группу. По умолчанию `creator` |
| `PORT` | Railway подставляет сам |

Те же токены прописываются и в `.env.prod` API (`TELEGRAM_*_BOT_TOKEN`):
подпись `initData` мини-аппа — чистая криптография над токеном, и
делать её здесь значит уронить вход в мини-апп вместе с этим сервисом.

## Выкатка

Сервис уже поднят: Railway, проект `illustrious-renewal`, сервис
`telegram-bots`, адрес
`https://telegram-bots-production-b666.up.railway.app`. Вебхуки обоих
ботов прописаны на него.

Повторная выкатка — из этой папки, и только из неё: `railway up`
загружает текущий каталог, а не репозиторий целиком.

```bash
cd deploy/telegram-bot
railway up --service telegram-bots
```

Если когда-нибудь подключите Railway к GitHub вместо `railway up` —
обязательно задайте **Root Directory = `deploy/telegram-bot`**. Без
этого он возьмёт `Dockerfile` из корня и соберёт Go-API вместо бота.

Вебхуки перепрописываются после смены адреса сервиса:

```bash
PUBLIC_URL=https://telegram-bots-production-b666.up.railway.app npm run set-webhook
```

Проверка живости: `GET /health` отвечает `{"ok":true,"bots":[...]}`.

## Чат менеджеров

Менеджерского бота нет: в группу пишет **креаторский**. Так у менеджера
одна привязка вместо двух, у нас одна очередь доставки вместо двух, а
мини-апп открывается из того же бота — своего ему не нужно.

Как подключить:

1. добавьте @prcreators_bot в группу менеджеров (если чат разбит на
   темы — в нужную тему);
2. отправьте там `/chatid` — бот ответит готовыми строками
   `TELEGRAM_MANAGERS_CHAT_ID=…` и, если это тема,
   `TELEGRAM_MANAGERS_THREAD_ID=…`;
3. пропишите их в переменные Railway и передеплойте.

Больше бот в группе не разговаривает: он туда пишет, а не отвечает.

Когда доставка через бота включена, API **перестаёт** слать те же
события в n8n: и туда, и туда — это два одинаковых сообщения в одной
группе. Чтобы вернуться на n8n, достаточно очистить `BOT_WEBHOOK_URL`
у API.

## Контракт с API

**Мы → бот.** `POST /notify`, тело — обычный payload outbox плюс два
поля:

```json
{
  "event_id": "12345",
  "event_type": "project.publication_due_today",
  "aggregate": "project",
  "aggregate_id": "…",
  "app_base_url": "https://wayprmarket.ru",
  "data": { "...": "payload события" },
  "bot": "creator",
  "audience": "person",
  "recipients": [{ "user_id": "…", "tg_chat_id": 482512345 }]
}
```

`audience` — кому это адресовано: `person` (личное, по списку
`recipients`) или `managers` (общий чат; `recipients` тогда пуст —
идентификатор группы знает только бот).

Коды ответа читает outbox API, и они значат ровно это:

| Ответ | Что делает outbox |
|---|---|
| `2xx` | принято |
| `408`, `429`, `5xx` | повтор с backoff |
| любой другой `4xx` | в DLQ, повторов нет |

Поэтому «бот не настроен» и «неизвестный тип события» — это `200`, а
не `500`: нормальная ситуация, превращённая в пятисотку, стоит десяти
ретраев. Дедупликация по `event_id` — на нашей стороне: API повторяет
при любой ошибке, и без памяти человек получил бы дубль.

**Бот → API** (`Authorization: Bearer $BOT_SHARED_SECRET`):

- `POST /api/v1/bot/link` — `/start` с кодом;
- `GET /api/v1/bot/users/by-telegram/{tg_user_id}?bot=` — «кто это»;
  `404` значит «не привязан», и это нормальное состояние;
- `POST /api/v1/bot/blocked` — человек заблокировал бота.

## Аватарки

`assets/avatar-creator.png` и `assets/avatar-client.png`, 512×512.
Одна геометрия и одна сетка на двоих, разный цвет и разный знак: у
креаторского — видоискатель с точкой записи (бот про съёмку), у
клиентского — растущая линия с точкой (бот про просмотры). По
картинкам должно быть видно, что это пара от одного продукта, и при
этом сразу понятно, который из них чей.

Ставятся **только через @BotFather** — Bot API менять аватар бота не
умеет: `/setuserpic` → выбрать бота → отправить файл.

Рисует их `scripts/avatars.py` в этой же папке: править цвет или знак
проще в коде, чем в редакторе, и результат воспроизводим.
